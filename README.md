# ICD Crosswalk Automation -- R Port + SapBERT vs. ClinicalBERT Comparison

Native R/RStudio port of Dr. Lix lab's ICD automatic-mapping pipeline
(originally `Pipeline_10_9_2024Nov27.ipynb` / `Pipeline_8_9_2024Oct30.ipynb`,
Python + pandas), plus a comparison of two embedding models -- ClinicalBERT
(the original) and SapBERT -- as the similarity signal that pipeline uses.

The pipeline maps ICD-9-CM codes to two other coding systems:

- **ICD-9-CM -> ICD-10-CA**
- **ICD-9-CM -> ICDA-8**

by combining embedding cosine similarity between code labels with
historical co-occurrence frequency, filtering by chapter distance, and
selecting candidates with one of four rule-based "flag combination"
strategies. Results are validated against a manually-curated crosswalk to
produce precision, recall, F1, and accuracy, overall and per CCS
diagnostic category.

## Folder structure

```

  original/
    Cosine_Similarity_Matrices/   ClinicalBERT cosine-similarity matrices (per CCS category)
    Co_occurrence/                ICD-9 <-> target code co-occurrence frequency tables
    ICD_Codes_Files_and_Validation_Data/
                                   code/label lookups, CCS category mapping, manual
                                   validation crosswalks (the "ground truth")
  sapbert/
    cosine_similarity_matrices_10_9_SapBERT.xlsx
    cosine_similarity_matrices_8_9_SapBERT.xlsx
                                   SapBERT cosine-similarity matrices, same shape/sheet
                                   layout as the ClinicalBERT ones -- already generated,
                                   safe to use as-is
    icd8_order.csv / icd9_order.csv / icd10_order.csv
                                   row order used when the SapBERT embeddings were generated

scripts/
  pipeline_lib.R                  Core pipeline: chapter definitions, similarity scoring,
                                   co-occurrence, flag-based selection, validation,
                                   precision/recall/F1/accuracy. Functions only.
  run_sanity_check.R              Reproduces Dr. Lix's published ClinicalBERT numbers.
                                   Run this FIRST any time you touch pipeline_lib.R.
  01_generate_sapbert_embeddings.R

                                   you're regenerating data/sapbert/ from raw text --
                                   the precomputed matrices are already there.
  02_run_comparison.R             Runs the full parameter grid (similarity threshold x
                                   top-N co-occurrence x flag rule) for both models on
                                   both tracks. Writes results/*.csv.
  03_visualize_results.R          Builds the comparison charts from results/*.csv.
                                   Writes results/*.png.

  grid_results_10_9.csv, grid_results_8_9.csv
```

## Prerequisites

**R packages** (already installed in this environment):
`dplyr`, `readxl`, `writexl`, `tidyr`, `ggplot2`, `reticulate`, `stringr`,
`purrr`. Knitting `report.Rmd` also needs `knitr` and `rmarkdown`.

**Python packages via reticulate** (only needed if regenerating SapBERT
embeddings from scratch): `torch`, `transformers`, already installed at
`/usr/bin/python3` and pointed to by `use_python()` in
`01_generate_sapbert_embeddings.R`.

## How to reproduce everything, in order

Run scripts from inside the `scripts/` directory (they use relative paths
like `../data/...`), e.g. by opening this project in RStudio and using
`setwd("scripts")`, or running each with `Rscript` from that directory.

1. **`run_sanity_check.R`** -- confirms the R port reproduces the
   published ClinicalBERT numbers exactly. Run this first, always. If it
   doesn't match, stop and fix `pipeline_lib.R` before doing anything else
   -- nothing downstream can be trusted otherwise.
   ```r
   source("run_sanity_check.R")
   ```

2. **`01_generate_sapbert_embeddings.R`** -- *optional*. Only needed if
   you want to regenerate `data/sapbert/*.xlsx` from raw code/label text.
   The precomputed SapBERT similarity matrices are already in
   `data/sapbert/` and verified correct; skip this step unless you have a
   specific reason to regenerate them (e.g. changing the model, the
   candidate universe, or the max-length truncation). It downloads the
   ~440MB SapBERT model on first run and is slow on CPU (profiling notes
   for anyone optimizing this are in the script's header comment).

3. **`02_run_comparison.R`** -- runs the full parameter grid for both
   models, both tracks, and writes `results/*.csv`. Takes a few minutes
   (256 pipeline runs, each re-scoring the full candidate set).
   ```r
   source("02_run_comparison.R")
   ```

4. **`03_visualize_results.R`** -- builds the comparison charts from the
   CSVs written in step 3.
   ```r
   source("03_visualize_results.R")
   ```

5. **Knit `report.Rmd`** (from the project root, not `scripts/`) to
   produce the meeting-ready HTML report:
   ```r
   rmarkdown::render("report.Rmd")
   ```
   or use the "Knit" button in RStudio.

## Known gotcha if you ever touch `01_generate_sapbert_embeddings.R`

Calling a PyTorch model directly through reticulate's R wrapper syntax --
`model(input_ids = ..., attention_mask = ..., ...)` or
`model$forward(...)` on an `AutoModel`-loaded object -- silently returns
**numerically wrong** output versus calling the same model normally in
Python (not an error, just different numbers). The current script avoids
this entirely by defining a plain Python function via
`reticulate::py_run_string()` that does tokenization + forward pass
internally, called from R via `py$embed_batch(...)`. This was verified
byte-for-byte correct against a Python-native reference embedding. Keep
this pattern if you rewrite the script.
